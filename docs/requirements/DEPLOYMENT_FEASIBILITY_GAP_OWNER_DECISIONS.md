**Recommendation — PROPOSED, NOT APPROVED:** Choose **Option C as the owner decision framework**, with Option A as the first proof experiment and Option B as the no-cost database alternative if Neon fails. Neither A nor B is a substantiated complete S$0 stack yet, chiefly because account eligibility, real email delivery and reliable protected daily off-site backup/restore are unverified. Reject Render Free PostgreSQL as the durable default and Koyeb under the current card restriction. This recommendation does not approve a provider, a gap disposition, or any stage gate.

## 4. Minimum proof-of-feasibility evidence and pass/fail

The solo developer owns collection; the project owner reviews the evidence and any change decision. The tests below are **planned**, not executed. Record service/account terms and UTC/Singapore observation time, revision, configuration with secrets redacted, commands, results, usage and failures. Use synthetic records and authorised test addresses.

| Check | Objective pass evidence; fail condition |
|---|---|
| Eligibility and billing | Actual accounts show allowed free plan, region, no required card/paid trial/automatic upgrade, quota and zero-charge safeguard; usage/billing screenshots or redacted exports at setup and after tests. Fail on any required charge, unbounded overage or ineligible account. |
| HTTPS and security | Public staging URL loads over valid HTTPS; session cookie is HttpOnly and Secure, CSRF-protected mutation with missing/invalid token is rejected without mutation, and scoped session access is enforced. Exercise the **approved G-07** 30-minute idle and 8-hour absolute limits, logout, deactivated-Staff denial on the next protected request and owner-controlled compromise revocation. Fail on HTTP-only access, insecure cookie, CSRF bypass, cross-inventory mutation or an access path that violates those approved outcomes. Exact token/session/throttle mechanism is Design work. |
| Database | Django 5.2 connects to PostgreSQL with certificate/TLS verification, applies migrations, writes representative stock/audit records, and reads same records after web restart and database idle/wake. Fail on connection, migration, persistence or integrity error. Record DB size and quota headroom. |
| Email | Authorised Staff invitation and password reset arrive in controlled inboxes through the HTTPS API with permitted sender identity. Verify **approved G-07** 24-hour single-use/latest-only invitation with scoped revoke/resend, 30-minute single-use/latest-only reset, old-session revocation after reset, generic public account feedback, safe eligible retry and approved login/reset/invitation threshold boundaries; tokens work only through intended links and are absent from public logs/screenshots. Fail on no delivery, unapproved paid/domain dependency, leaked token, account enumeration or account activation/password change from mere send attempt. | Daily backup and restore | Show an automated **daily** PostgreSQL export, success/failure alert, encryption, protected off-site retention independent of web ephemeral disk and database project, access controls and quota; restore one export into an isolated PostgreSQL database and compare representative product, batch, stock and audit records. A GitHub schedule/artifact alone is insufficient until its timing, privacy, storage and expiry are demonstrated. |

Fail if SQLite substitutes or failure stays green. Existing documentation CI is not this proof. |
