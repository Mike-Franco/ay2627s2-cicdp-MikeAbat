### Repository evidence and remaining requirements

The repository contains Django 5.2.18/psycopg, PostgreSQL settings, WSGI/ASGI entry points, environment-based configuration, staging security checks, migrations and a TORY-19 expiry-processing command. Django/PostgreSQL GitHub Actions CI already runs checks, migrations and tests against PostgreSQL; Documentation CI separately runs the Markdown checker. CI existence does not prove staging eligibility, private-repository quotas, backup, restore, or provider fit.

The application requires PostgreSQL `track_commit_timestamp=on` for demand attribution and uses PostgreSQL functions to obtain transaction commit times. TORY-19 requires an idempotent expiry command every five minutes, with monitoring and recovery before the approved one-hour evidence limit. These are compatibility and operations gates for any selected database/scheduler. Provider support and actual account configuration remain unverified.

Manual reseeding or keeping a local dump is not compliance with NFR-008: the requirement is a protected daily off-host PostgreSQL backup and at least one demonstrated restore to an isolated database. No backup destination, retention, recovery objectives, backup automation, alerting, or restore evidence exists in this review. A restored database also requires a safe policy for pending commit-time records: source transaction IDs cannot be assumed meaningful on a different PostgreSQL cluster.

Secure deployment configuration, static-asset collection/serving, trusted proxy and database TLS settings, initial Tory Manager membership/assignment provisioning, and invitation/reset email delivery also remain unimplemented or unverified. A Django superuser alone does not establish Tory business membership and inventory assignments.
